## 产品目标

> 本节为 2026-08-28 收敛前的历史语义，现行定位见上方"当前产品定位"。

建设一套自主可控的 AI 智能体 RPA。产品必须是能够持续观察、记录执行路径、按需调用模型、等待、换路、报告能力缺口并从检查点续跑的 Loop Engine，而不是只能执行预定义步骤的单一工作流。项目维护流程可在浏览器任务之外修复和验证工具代码，但执行层大模型没有项目修改权限。第一阶段只实现浏览器自动化，正常任务从接收目标到执行、校验、重试和恢复均不依赖人工逐步操作。系统必须优先保证执行速度、定位准确性、可恢复性和长期可维护性。

浏览器自动化只是首个驱动，后续还要扩展窗口自动化。因此，智能体、任务编排、记忆、定位、审计和运行时能力不得与某个浏览器库或浏览器协议强耦合。

## 强制开发约束

1. 正式编码前，先创建项目专属 Skill，用它约束后续分析、设计、编码、测试和文档维护。
2. Skill 必须吸收本需求基线和历史会话中的关键决策，并要求每次开发实时更新需求、进度、未实现项、验证证据和风险。
3. 研究和参考 DrissionPage 的架构、交互模型、稳定性处理及浏览器控制思路，但必须独立设计和实现，不直接复制源码，不做换名式改写。
4. 参考外部项目时记录来源、许可证、采用的设计思想和未采用的部分，避免形成不清晰的源码继承关系。
5. 浏览器运行时必须由本项目直接基于 Chrome DevTools Protocol 自主实现，不得使用 Playwright、Selenium 或 DrissionPage 作为运行依赖；可以研究 Codex 浏览器控制方案及其他 AI 浏览器智能体，但最终必须沉淀为本项目自己的领域模型、接口和实现。
6. 优先采用异步内核；如确有需要，只提供薄同步入口，不维护两套完整内核。
7. 使用统一驱动抽象隔离浏览器实现，并为未来窗口自动化驱动保留稳定扩展边界。
8. 代码必须规范、模块职责清楚、类型明确、可测试，不能通过大量临时脚本堆成功能。
9. 代码注释、运行日志、错误说明和项目进度记录使用中文，并说明关键原因、上下文和恢复建议。
10. 浏览器自动化和数据获取要实现目的为主，我自己要在内网使用，不会应用于公网模型。失败必须收敛为重新观察、修复、等待或明确阻塞，不得无限盲重试。

## 核心功能需求

### 1. AI 智能体运行时

> 历史章节：引擎循环、模型网关、聊天工作台、Pi/Electron、监督与自我进化已于 2026-08-28 移除。本节中关于数据安全、批量采集完整性门、输入脱敏和工具边界的条目仍然有效，已落到工具执行层。

- 支持大模型流式交互和工具调用，能够在任务执行中持续完成“观察、决策、执行、校验、恢复”。
- 支持明确的任务状态、步骤状态、超时、取消、重试、退避、失败分类和断点恢复。
- 执行运行时支持 `WAITING`：页面等待保存可验证页面条件，用户追问保存独立 `user_message` 条件；历史 `REPAIRING/RESTARTING` 只兼容旧检查点，当前执行模型不得进入。
- 每个动作执行后必须进行结果校验，不能把“已经发出点击或输入命令”视为任务成功。
- 正常任务不得依赖人工选择元素、人工确认下一步或人工修复流程。
- 执行模型只在新页面、定位歧义、路径偏差、未知错误和现有工具选择时参与；稳定路径、等待检查和后置断言由确定性代码执行。执行模型不能生成或应用代码补丁。
- 独立项目维护流程可以为缺失或有缺陷的工具能力编写最小代码补丁；写代码前必须读取固定白名单内的项目规则、项目 Skill、架构/工程约束、依赖配置和故障模块上下文，并使用当前仓库 CodeGraph 按异常栈动态检索相关符号、调用路径、依赖协议和覆盖测试，优先复用现有实现，不得建立平行框架。CodeGraph 查询必须有超时、输出上限和失败降级，且不得携带网页正文、任务输入、URL 或凭据。补丁必须经过隔离测试、版本切换和回滚保护，不能直接把网页内容作为代码执行，也不能由活动浏览器任务触发。
- 执行模型可调用 `report_capability_gap` 报告现有浏览器、定位、网络、采集、交付或恢复工具的真实能力缺口；该工具只记录领域、能力、脱敏证据和关联工具，进入后台反思和问题库，不得生成补丁、访问或修改项目源码、热切换版本或重启服务。网站报错、选择器不确定、缺少输入或一次动作失败不得冒充能力缺口；验证码阶段不得开放该工具。
- 执行模型只在缺少页面、任务输入和工具结果均无法推导的业务事实、目标存在真实歧义或需要不可逆业务选择时调用 `ask_user`。运行时必须把问题保存为 `user_message` 唤醒条件，只监听当前任务消息，不调用浏览器页面验证；用户回答后清除等待条件，在同一任务、同一页面上下文继续。技术不确定、尚未尝试工具、页面可观察事实和已有输入不得转嫁给用户。
- 独立项目维护流程发布代码时必须避开活动浏览器任务，保留验证记录和回滚；不得借用执行模型的任务检查点触发补丁应用或服务重启。历史 `RESTARTING` 检查点仍可被工作台识别和明确终止，但不再由当前执行链创建。
- Electron 判断 Python 子服务就绪时必须校验本次启动的唯一实例令牌，不能仅凭端口已有页面可访问；只有当前被托管子进程的退出事件可以触发自动重启。初始启动和异常恢复必须共用单一异步启动门，同一时刻只能有一个等待就绪的子进程；旧端口未释放时重新选择空闲端口，旧子进程和启动失败的旁路进程不得造成重启风暴。
- 当安全策略、权限不足或不可恢复错误阻止任务时，应自动停止并给出中文原因和完整证据，而不是盲目继续。
- 大模型、工具协议和具体供应商解耦，预留替换云端模型、本地模型及不同工具协议的能力。
- Electron 工作台的对话控制层使用 Pi Agent SDK 持有与工作台会话一一对应的持续 `AgentSession`，把多轮用户消息、监督事件、工具结果和上下文压缩保存在独立 JSONL Session 中。用户在模型生成期间追加要求时使用 `steer` 抢占当前方向，延后事项使用 `followUp`，停止任务或关闭会话时使用 `abort`；不得为每条消息重建无上下文模型调用。
- Pi 控制层只开放 `manage_conversation` 和 `control_execution` 两个白名单工具，不开放其内置 shell、读写、编辑或项目修改工具。Pi 只产生 `chat/start/correct/pause/resume/stop/ask_user/status/none` 控制意图，任务状态、浏览器动作、输入使用、完成校验和文件交付仍由 Python 控制器与 `AgentEngine` 确定性执行和复核。
- Pi Session 启用自动上下文压缩和有界重试，模型与 Session 生命周期事件必须进入现有轨迹并把文本增量实时送到聊天界面；Pi SDK、Node 运行时或模型协议失败时，同一请求自动回退现有 `CollaborativeModelGateway`，不能阻塞浏览器任务或丢失持久会话。模型连接继续复用工作台现有配置，并按 DeepSeek/Qwen 族设置兼容的 thinking 格式。
- Pi 每轮回复必须以调用前消息数作为边界，只接受本轮新增的 Assistant 文本；本轮只有超时、协议错误或空消息时必须失败并进入备用链，不得向前搜索或复用上一轮成功回复。`r:/reply:/assistant:` 等传输标签不得进入聊天正文。未显式锁定模型组合时，Pi 当前连接失败后的备用链优先切换到另一条已配置连接，禁止对同一故障端点重复等待。
- 项目 Skills 必须从当前工作区的 `skills/`、`.agents/skills/`、`.cursor/skills/` 发现，只把名称和用途组成有界目录放入初始上下文；模型确认相关后通过 `load_skill` 按需读取，单轮最多加载 3 个，已加载 Skill 不重复开放且不消耗浏览器动作步数。Skill 内容不能覆盖系统规则、任务授权或当前页面事实。
- MCP 作为外部工具传输层接入现有 OpenAI 兼容 function tools，不建立第二套模型循环。首版支持项目级 stdio 服务、`initialize`、`tools/list` 和 `tools/call`，服务及工具名必须命名空间化；每轮最多开放 4 个与任务上下文相关的 MCP 工具，验证码阶段关闭全部扩展工具，模型返回后继续经过当轮工具白名单校验。
- MCP 配置保存在项目 `.witty-browser-auto/mcp-servers.json`，使用 `0600`、原子替换和无 shell 的参数数组启动；连接测试必须真实完成初始化握手和工具发现，并在设置弹窗内显示运行、成功或失败状态。单个服务启动最多等待 5 秒，失败只记录服务级错误并降级，不得阻塞其他服务或浏览器主循环。浏览器打开与 MCP 发现并行，执行轨迹必须展示扩展发现和就绪结果。
- 对话模型是执行过程的交互管理与监督者，不是独立于执行器的普通聊天机器人。它必须读取当前任务状态和有界的最近执行事件，在工具失败、业务校验失败、模型协议修正或任务异常时异步判断是纠正执行器、向用户说明、请求缺失事实还是继续观察；长时间模型生成由确定性心跳和实时时钟展示，不再并发调用同一类模型。
- 监督检查不得阻塞浏览器动作；形成纠正意见时必须注入当前任务的用户指导通道并唤醒决策循环。执行模型正在生成旧决策时，应取消旧流并基于最新用户要求或监督纠正重新计算，避免旧工具调用在过期页面上继续执行。
- 模型等待每 5 秒产生可见心跳，记录本轮耗时和有界上下文指标；历史观察和工具往返必须压缩，只保留当前观察、最近控制消息和最新工具轮次。用户在运行中询问进度或故障时，对话模型基于实时事件流式答复，不得只返回固定状态语。
- 普通模型等待心跳只负责状态和耗时可见性，不得在同一连接上并发启动第二个监督请求争抢推理资源。监督模型只处理已经形成的工具失败、业务校验失败、协议修正或任务异常；模型长时间生成由当前请求的有界超时、用户抢占和界面实时时钟管理。
- 任务输入是否可用、是否已经成功使用必须由执行器维护并写入检查点，模型只接收输入键集合，不接收输入值。Authorization、Cookie、Host、API Key、Token 等运行时槽位可在任务执行中由用户补充，槽位参与任务签名而值不参与，补值后必须唤醒当前循环且不能破坏检查点身份。监督模型请求用户补充事实时必须声明 `required_input_keys`；若这些键已经存在，控制器必须把请求改为执行纠正并要求执行器使用已有输入，不得重复询问用户。
- 批量结果页只能向模型提供真正可操作的表单控件和分页导航候选，业务记录行不得以空名称候选、重复 target ID 或工具枚举进入请求。观察文本、工具 target enum 和可见候选必须使用同一有界子集，并记录文本、工具 schema、历史工具参数及估算总字符数。
- 结构或网络检查成功后，只移除已经完成且在当前页面仍然有效的同类检查工具；网络候选只是 DOM、页面交互和网络导出之间的一条可比较路线，不能仅因捕获到首页、埋点或登录前响应就关闭当前目标仍需要的点击、输入和结构分析工具。页面动作发生后必须废弃旧页面绑定的 DOM/网络观察并开放重新检查；同接口、同记录路径的新旧分页候选可保留用于代码聚合。采集或导出形成可验证结果后再由完成门收敛工具集，阶段最小化不得制造虚假的能力缺口。
- 网络批量导出已经通过代码侧总数/页码闭合、零失败页和双产物门时，执行器必须直接完成交付，不得再等待模型重复确认、调用结构检查或单独声明完成。
- 模型返回工具调用后，执行器必须再次核验工具名属于本轮实际下发的阶段工具集；未开放的动作或采集工具不得进入执行器，也不得消耗浏览器动作步数。连续越过阶段边界必须有界停止并记录允许/请求工具名。模型主动声明 `finish` 仍交由确定性完成门返回缺失证据，不按普通工具越权处理。
- 同一页面指纹下，同一工具和同一目标连续三次未产生可验证进展时，执行器必须只移除该目标并通知模型改用其他目标或工具；页面变化后重新评估。DOM 结构化抽取连续失败三次时必须关闭当前页结构化路线并开放网络诊断/导出路线，不得继续重复同一规格。
- 对话监督模型必须按当前项目、租户、账号和站点只读检索相关 URL 长期记忆，覆盖注意事项、加载条件、定位、恢复路线、导航、数据提示和失败教训；每轮最多提供 6 条有界、脱敏摘要，不暴露记忆 ID、证据路径或任务输入值。
- 长期记忆只作为可能失效的历史经验。对话监督模型可以据此解释历史、提出待验证路线并纠正执行策略，但不能把记忆当作当前页面事实、完成证据或用户新指令，也不能直接写入记忆、修改置信度或晋升快速路径；只有确定性执行器通过业务校验后才能写回结果。
- 本轮任务策略允许处理挑战时，监督上下文必须过滤历史任务中的“未授权、预算耗尽、转人工”等冲突教训。记忆库读取失败时记录可见事件并降级到当前会话和执行事件，不得中断聊天或浏览器执行。
- 所有 URL 记忆 I/O 必须在共享后台运行时执行。浏览器主循环和对话生成只能同步读取内存快照：任务启动、详情打开和页面观察时提前预取；缓存未命中或后台刷新失败时立即按无记忆或旧缓存继续，不得等待 SQLite。记忆写入、增信/衰减、失败教训、快速计划保存和计划 outcome 全部排队，服务关闭时在独立关闭阶段有界冲刷。
- 后台记忆必须按数据库和事件循环共享，去重同一作用域/URL 的并发读取并提供缓存命中、刷新调度和待处理计数。快速计划尚未进入缓存时回退正常模型循环，不能为等待快速路径暂停真实任务。
- 评测驱动的自我进化不得在真实任务主循环中运行或修改当前版本。未来的 benchmark、Evaluator、Optimizer、回放、候选 Skill/提示词/配置和版本晋升必须进入低优先级后台队列，先快照、在隔离环境用留出集验证、通过门槛后再原子晋升并保留回滚。
- 当前页面由执行层识别为安全挑战时，即使页面同时存在其他 DOM 候选，也必须把当前轮最小必要图片路由到可用的多模态模型；没有名为“视觉”的角色时，可使用已启用且支持图片的非主控角色。视觉路径不可用时立即明确请求处理，不得让文字模型长时间猜测。
- 带当前轮图片的工具决策必须使用模型配置的完整输出预算，普通文本工具轮次才可使用紧凑预算；不得因统一 token 上限把验证码视觉工具参数截断后反复重试。
- 验证码必须使用执行器阶段机维护 `idle/ready/text_entered/awaiting_result`。模型输入识别文字后只能提交；提交后挑战仍可见必须记录一次失败并重新观察当前图，不得复用旧文字。是否继续由模型基于最新页面、截图、失败原因和已执行策略动态判断，不得按固定累计次数停止。
- 安全挑战上下文必须向模型公开代码维护的当前阶段、审计尝试次数和已执行策略签名。文本验证码即使没有被拖拽风险分类器识别，只要已进入挑战且当前仍需要图片上下文，也必须使用最小挑战工具集，不能重新开放普通页面的全部工具。同一截图和页面观察上的等价答案或拖拽策略必须在输入派发前拒绝；截图、页面或轨迹参数实质变化后允许模型继续。
- 大模型负责识别验证码内容和选择当前提交目标；观察指纹、截图指纹等动态校验值由执行层绑定到当前轮工具 schema，并在验证码提交阶段由执行器规范化，禁止要求模型从压缩历史复制或复用旧值。验证码文字中的模型格式空白必须在挑战专用路径清理，清理后仍存在的控制字符继续拒绝；普通模型生成文本不得放宽。
- 验证码进度事件以代码维护的尝试编号去重，同一次尝试内的区域放大、截图刷新或页面指纹变化不得重复显示“第 n 次识别”；只有实际提交失败并进入下一次尝试后才能增加编号。
- 异步监督结果在主任务进入终态后不得再写入聊天或执行指导队列；应记录为迟到结果并丢弃。重复动作的停止门必须由执行器保证，不能依赖监督模型是否及时返回。
- 获取订单、列表、明细等批量数据时，大模型只负责理解用户提示词并生成受控字段、过滤和分页规格；页面结构分析、逐页读取、去重、过滤、计数、完整性校验和导出必须由代码执行。
- 用户提示词改变所需字段或过滤条件时，智能体应在同一决策循环中提交新规格并让代码重新采集；不得让模型逐条补充、删改或复述业务记录。
- 模型上下文只能接收采集计数、页数、失败原因、完整性证据和产物路径，原始记录只进入受权限保护的 JSON/CSV 结果文件。
- 用户在对话中指定输出目录或 Excel/CSV/JSON 格式时，控制器必须把它解析为任务执行契约而不是仅保留在提示词中。完成门必须在指定目录原子写入目标文件并重新打开校验；交付失败时任务进入失败终态，模型不得用文字声称已经保存。没有显式目录但指定格式时，交付到当前任务的私有产物目录。
- 已成功任务收到“把现有数据保存/导出/移动/复制到另一个绝对目录”或补充输出格式的续聊要求时，控制器必须直接复用当前任务的已验证文件，在本地原子复制并重新打开校验；需要 Excel 时可由已验证 CSV 本地生成。该路径不得调用对话模型、创建新任务、打开浏览器或重新采集。原始交付文件作为任务证据保留；只有用户明确要求重新采集、重新抓取、更新或获取最新数据时才进入新的浏览器执行。
- 所有数据获取任务都必须在启动时绑定当前任务独占的默认交付目录；即使用户没有指定目录或格式，也不能把中间采集目录、浏览器下载目录或其他任务的历史路径当作交付结果。直接调用执行引擎时，默认目录必须位于已验证源文件同级的 `deliverables/`。
- 数据任务只有在完整性门通过、至少一个交付文件真实存在且按格式重新打开校验成功后才能进入成功终态。终态快照必须包含当前 `task_id`、阶段、步骤、耗时、记录数、页数、证据数、最后成功动作、阻塞原因、下一步，以及交付文件绝对路径、格式、字节数和验证状态。
- 每条持久执行事件必须带所属 `task_id`；工作台、对话模型和监督模型只能从当前任务事件构建快照，不能让同一会话的旧任务终态、旧文件路径或旧阻塞状态污染新任务。
- 登录/认证等待、页面恢复、验证码开始与结果、采集分析、采集开始、部分记录数、分页未闭合、完成校验、工具失败和换路必须以有界生命周期消息主动进入聊天。右侧运行面板展示同一任务快照和已验证交付文件；原始模型思考与详细轨迹继续放在可折叠、可滚动区域，不代替面向用户的进度沟通。
- 任务终态必须先持久化智能体聊天消息，再发布终态事件，确保前端看到“完成”时对应结果已经可读。聊天输入框保持焦点不得暂停会话刷新；刷新不得覆盖用户尚未发送的输入。
- 批量数据保护必须覆盖模型的全部观察通道：不得通过页面截图、原始 DOM 摘要、候选文本或结构样例把业务记录发送给模型；结构观察只提供选择器、数量、角色和允许的数据来源类型。
- 多模态触发必须理解否定语义并验证目标可见；“禁止截图”“不要通过截图接收数据”等描述不能开启截图，隐藏验证码节点和普通说明文字也不能单独触发图片上传。
- 明确要求全部或所有数据时，没有代码侧强完整性证据、存在失败页或缺少 JSON/CSV 任一产物，必须拒绝任务完成。
- 分页识别覆盖下一页、页码、加载更多、无限滚动，以及接口 `page/size`、`offset/limit`、`cursor/token`；DOM 四种形态由确定性代码遍历，尚无遍历器的网络分页必须保持未完成或阻塞，不能退化为只导出当前页。
- 单个页面或单个网络响应默认是部分结果。即使结果只有一页，也必须由代码证明声明总数与去重数闭合、声明总页数已经覆盖或已经稳定到达分页终点，模型判断和“未看到下一页”不能单独作为证据。
- 同一接口已经由浏览器捕获多个分页 JSON 响应时，网络工具必须接受单个 `candidate_id` 或有界的 `candidate_ids`，由代码校验同接口和同记录路径、聚合并按规范 JSON 去重。只有接口声明总数与聚合数一致，或显式页码覆盖声明总页数时，批量响应才可标记完整；进入网络补充路径后，完成门以网络结果为准，不能让先前完整但字段更少的 DOM 列表掩盖不完整的详情结果。
- DOM 与网络聚合结果同时通过完整性门时，应交付后进入的网络补充结果，避免用户要求详情字段却收到先前的基础列表文件。网络聚合仍不主动发送额外请求；缺失响应时必须回到可观察的页面动作捕获缺页，或保持未完成。
- DOM 页码模式必须读取当前页并确保从第 1 页开始，逐页覆盖声明总页数；加载更多和无限滚动按累积快照合并，历史快照重现的行不虚增业务重复计数。
- 无限滚动必须连续 2–5 次滚动到底且列表指纹均不变化才形成终点证据；达到最大页数仍有新数据、翻页后无进展或声明计数不闭合时不得导出。
- 完整性证据必须进入脱敏任务事件和持久路径，至少记录数据来源、已访问页/响应数、声明总数/页数、去重数、重复数、失败页、完成依据和双产物状态；不得记录原始业务行。

### 2. 浏览器自动化

- 浏览器启动、接管、复用、关闭、崩溃检测和异常重连。
- 页面和标签页的创建、切换、关闭、导航及状态管理。
- 元素定位、点击、输入、选择、滚动、悬停、读取文本和属性；观察候选不可用时允许模型提交 CSS、XPath、role/name、text、label 或 test-id 显式定位器。
- 支持语义目标相对拖拽，以及与当前截图指纹绑定的视口比例视觉拖拽；所有拖拽均携带执行层风险分类，视为非幂等动作并强制校验结果。
- 视觉动作成功条件在动作前必须为假；当前页面已存在的挑战标题、URL、文本或目标不能被用作动作后置成功证据。
- 安全挑战只有一个可见长条轨道时，确定性代码必须结合 CSS 视口与轨道盒约束手柄起点、终点和容差；模型坐标越界时先返回修正建议，不派发鼠标也不消耗挑战次数。
- 视觉拖拽必须覆盖接近、悬停、按下停顿、非线性有界移动和释放，并在可见浏览器中用不参与页面命中的 DevTools Overlay 同步展示指针轨迹；Overlay 不可用只降级可见反馈，不能中断真实输入。动作审计保存是否显示可视指针且不含页面业务内容；按下后的异常继续按结果未知处理。
- 页面、元素、导航、下载、网络响应和业务条件等待。
- JavaScript 执行和页面结构化状态读取。
- Cookie、存储状态、登录会话、账号和浏览器配置隔离。
- 上传、下载、弹窗、iframe 和 Shadow DOM 等复杂交互应进入完整项目能力范围，具体版本优先级后续确定。
- 失败时保留截图、页面快照、动作轨迹、网络摘要和中文日志。

### 3. 准确区域定位

- 建立统一的页面观察模型，不让智能体只依赖脆弱的 CSS 选择器或屏幕坐标。
- 优先结合 DOM、可访问性树、文本、控件语义、页面结构和历史记忆定位目标。
- 为视觉截图、OCR、视觉模型和坐标操作预留降级路径，用于无语义控件、Canvas 或复杂页面。
- 当模型明确配置为支持图片输入时，可把当前轮截图作为 OpenAI 兼容多模态消息发送；历史轮次只保留文本观察，避免重复上传旧截图。多模态模型提供感知结果，最终风险授权由确定性执行层判定，不能依赖模型自行声明。
- 定位结果包含候选区域、置信度、依据和可执行动作；低置信度时自动扩大观察或换用其他定位策略。
- 显式定位器必须有界等待并在执行前重新验证唯一、稳定、可见、启用、未遮挡和可命中；匹配多个元素且未显式给出 index 时停止消歧，不得默认点击第一个。临时 DOM node/object ID 不得进入模型或跨导航保存。
- 显式定位器是观察候选失效时的动作降级，不替代批量结构化抽取的受控 CSS 规格；模型提供的 XPath 只作为 CDP DOM 搜索查询，不作为 JavaScript 或本地代码执行。
- 动作前校验目标区域，动作后校验页面效果，防止相似文本、遮挡层和页面漂移导致误操作。
- 无布局框、不可见或面积小于 1 的 DOM 控件不得进入模型候选；动态挑战截图变化时，只有重新获取的只读语义观察指纹仍一致才可有限执行。
- 精确几何和完整指针序列仍被站点侧挑战拒绝时，任务必须有界停止并标记外部条件阻塞；自有站点应提供专用测试来源白名单、测试绕过或授权业务/API 通道，不能用无限重试代替稳定集成。

### 4. 基于 URL 的记忆

- 以规范化 URL 为主索引，同时支持精确页面、路径模板、站点和业务场景等不同作用域。
- 执行任务前自动检索当前 URL 的相关记忆，任务完成后只把经过验证的经验写回。
- 可记忆页面注意事项、稳定定位依据、加载完成条件、快捷执行路径、成功工作流、失败模式、恢复方法、页面跳转关系和可复用的数据接口线索。
- 记忆项包含来源、作用域、版本、置信度、创建时间、最近验证时间、失效条件和使用效果。
- 页面变化或执行失败时降低旧记忆置信度，不允许永久盲信历史选择器或路径。
- 记忆按项目、租户、站点和账号边界隔离；密码、令牌、Cookie 等敏感信息不得以明文经验记录。
- 高频成功路径应可编译或缓存为快速执行计划，在环境一致时减少大模型调用和重复页面观察。

### 5. 网络分析与数据获取扩展

- 第一阶段已实现页面 DOM 的提示词驱动结构化采集、受限的只读网络 JSON 响应体抽取与接口候选识别，以及任务级同源 CDP Fetch 路由；数据采集和路由修改是不同能力，不能互相冒充完成。
- 网络捕获只处理任务授权 origin 内、浏览器已经发起的 `XHR/Fetch`、`2xx`、JSON 响应；限制单体字节数和内存保留数量，不主动发送额外请求。
- 模型只接收去除查询参数的接口地址、方法、状态、大小、评分和 JSON 字段结构；完整响应只由代码写入 `0600` JSON，识别到记录数组时同时写入 `0600` CSV。
- 单响应导出默认未完整；已捕获的最多 50 个同接口、同记录路径响应可由代码聚合、规范去重，并在声明总数或总页数闭合时形成完整证据。主动生成分页请求、游标遍历和缺页补抓仍需独立实现。
- 模型可用 `manage_network_route` 列出、新增或删除当前任务规则；规则最多 8 条，只允许任务授权 origin，支持阻断、修改请求方法/正文/Header、模拟响应，以及修改响应状态/正文/Header。规则变化后执行器必须重新开放页面动作，触发请求后再观察或导出，不能把旧候选当作新响应。
- Authorization、Cookie、Host、令牌和 API Key 等敏感 Header 只能通过任务 input_key 注入，模型不得接收或回显值；Host 必须按 Chromium 约束编译为保留路径与查询的 URL authority 重写，`Content-Length` 继续由浏览器管理。不允许匹配 host 通配符，不向模型回显 Header 值或正文。每个暂停请求无论匹配、失败或无规则都必须由确定性代码继续、阻断或完成，不能悬挂页面网络。
- 捕获配置必须在本地配置中心提供中文开关、单体大小和保留数量；作用域校验不能通过配置关闭。
- 任务级路由只拦截浏览器本来就会发起的请求，不等于独立 HTTP 请求复现。没有域名、方法、路径、速率、账号作用域和会话证据策略前，不得把网络路由误报为主动分页、完整逆向或接口直连能力。
- 后续能够把浏览器中发现且用户有权调用的接口转换为更快的数据获取路径，并复用受控会话状态。
- 网络模块与浏览器动作模块解耦，使任务可以选择页面操作、接口读取或两者组合。
- 记录数据来源、请求上下文、响应证据和抽取过程，支持审计与问题复现。
- 不在该扩展中加入破解加密、绕过身份验证、绕过访问控制或规避网站安全机制的能力。

### 6. 性能要求

- 速度是核心指标，需要建立可重复的基准任务并持续记录总耗时、模型耗时、定位耗时、浏览器动作耗时和网络耗时。
- 优先复用浏览器进程、连接、登录会话、页面知识和已验证执行计划。
- 页面观察采用增量更新，避免每一步都向大模型传输完整 DOM 或完整截图。
- 无依赖的读取、观察和预处理可以并行；会改变页面状态的动作必须保持确定顺序。
- 当已验证的接口数据路径比 UI 操作更可靠且符合权限要求时，允许智能体选择更快路径。

### 7. 可观测性和项目状态

- 日志采用结构化格式，展示任务、步骤、页面、动作、耗时、结果、重试原因和关联证据，面向开发者的说明使用中文。
- 保留可查询的任务轨迹，支持复现大模型决策、工具调用、页面变化和记忆命中情况。
- 每次需求变化都要记录时间、来源、影响范围和验收条件。
- 每次实现都要同步标记“已实现、部分实现、未实现或阻塞”，并附验证命令或人工验收证据。
- 不得仅依据代码存在就标记为已实现，必须通过测试或可复现的验证场景。

### 8. Loop Engine、人机协作与自修复

- 当前任务允许处理挑战时，模型不得只因历史上限、固定次数或笼统的自动化失败结束；终态门必须公开当前审计计数，并要求模型依据最新页面事实说明刷新、换策略、询问用户或阻塞的具体理由。
- 工具代码错误必须隔离本轮故障工具、保存最小脱敏证据并让模型从其余现有工具换路；缺口在任务终态后由后台反思去重记录，项目维护者通过独立开发、测试、发布流程补充框架能力。
- 人类提供目标、完成条件、合法凭据和无法推导的业务事实，并能暂停、修正或接管；智能体承担正常执行、等待、诊断、修复和续跑。
- 暂停必须是可恢复控制动作：当前原子浏览器步骤结束后进入暂停门，保持同一任务 ID、浏览器、检查点和执行上下文；恢复时必须先原子持久化 `running` 状态和恢复事件，再唤醒原执行器，防止快速完成结果被迟到状态写回覆盖。暂停不等于取消，恢复不得新建任务。
- 提供持久聊天会话作为任务控制面：开始执行前可连续补充需求，执行中用户消息必须进入当前决策循环；等待登录或页面条件时，新消息可立即唤醒而不必重启任务。
- 用户发送首条任务消息时，当前任务已填写的起始网址和执行选项必须在同一次请求中提交：网址先规范化并持久化，再自动启动执行。尚未提交的网址草稿按会话隔离并可从页面刷新恢复；切换任务时不得沿用另一个任务的输入框值。
- 用户把网址写在聊天正文时，控制器必须从用户消息提取、规范化并按会话持久化；旧草稿的地址字段为空时，应从历史用户消息恢复，不得相信模型回复中复述的网址。已有网址的草稿、等待或终态会话收到新消息后，是否启动或继续必须由对话管理模型通过受控 `manage_conversation` 工具选择 `start/chat`，不得用关键词列表代替模型意图识别。只有控制器真实创建任务 runner 后才能回复“任务已开始”。
- 消息已记录、自动启动、启动失败和执行异常都必须形成持久的智能体聊天消息或明确状态；不得只依赖短暂 Toast、右侧轨迹或本地日志表示结果。
- 用户在可见浏览器中的点击、字段变更和提交必须记录来源、时间、页面和稳定定位属性，用于实时展示、审计和后续路径学习；不得记录输入值、密码、令牌或敏感查询参数。
- 工作台必须同时显示对话、任务状态和增量事件；用户可以停止任务、在阻塞后补充事实并以同一会话再次执行。控制面与 `AgentEngine` 通过稳定交互协议连接，不能让 HTTP/UI 逻辑进入核心决策器。
- 用户最新明确的暂停、停止和关闭浏览器命令高于历史采集目标。关闭浏览器必须在模型意图路由前确定性处理：中止当前任务和 Pi 轮次、删除待续跑记录、关闭持久驱动，并在控制器核实结果后回执；`stop` 与 `close_browser` 是不同控制动作。
- 当前任务状态、交付和右侧执行轨迹必须按 `task_id` 隔离；新任务不得继承旧任务的记录数、页数、文件或迟到终态事件。
- 对话、监督和任务快照读取有界事件上下文时必须读取最新 N 条并保持正序；不得把 `LIMIT N` 误用为会话最早 N 条，导致长会话丢失当前任务状态。
- 真人操作记录自动归纳为稳定定位配方或可复用代码前，必须经过脱敏、前后置条件补全、重复验证和回滚保护；仅有事件记录不得标记为成熟路径。
- 稳定路径应逐步降低模型参与率；只有经过重复执行、页面漂移、失败恢复和版本回滚验证后才能标记成熟。

## 架构边界

完整项目至少划分以下职责，最终模块名可在架构设计阶段调整：

- `Agent Core`：目标理解、规划、决策、校验和恢复。
- `Loop Engine`：执行状态机、路径选择、模型介入门控、等待唤醒、检查点、故障工具隔离和能力缺口记录。
- `Automation Driver`：统一自动化驱动接口；首个实现为浏览器，未来增加窗口驱动。
- `Observation & Localization`：DOM、可访问性、视觉和区域定位。
- `URL Memory`：作用域解析、检索、写回、失效、隔离和快速路径。
- `Network & Data`：网络事件、请求复现、数据抽取及未来逆向分析扩展。
- `Runtime`：任务状态、重试、取消、并发、事件和资源生命周期。
- `Model Gateway`：大模型流式交互、工具协议、上下文控制和供应商适配。
- `Storage`：任务、记忆、证据、配置和结构化结果持久化。
- `Observability`：中文日志、指标、轨迹、截图和诊断产物。

## “无人干预”的当前定义

“无人干预”指满足运行前置条件的任务能够自主规划、执行稳定路径、按需调用模型、定位、校验、等待、修复工具和从检查点续跑，不把人工选点、逐步确认或人工改代码作为正常流程的一部分。缺少无法推导的业务事实、凭据或外部授权时，系统保存检查点并明确请求人类补充；信息补齐后继续原任务。

开发验证模式用于外网网页或企业测试环境的工具调优。在明确列出的测试 origin 和专用 profile 内，普通、视觉和挑战样式页面动作可以自动执行，风险标签只用于轨迹、诊断和后续生产策略设计，不要求每一步人工确认。重复无进展时必须转入模型诊断、代码修复或智能等待。该模式不扩大任务作用域，也不提供凭据猜测、认证/MFA/访问控制绕过或浏览器指纹伪装。
